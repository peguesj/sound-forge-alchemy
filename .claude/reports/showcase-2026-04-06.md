## Session Work (2026-04-06)

### Cohesive MIDI Device Management

Root cause: `DeviceManager.list_devices()` returned 14 raw Core MIDI ports for 2 physical
devices. Templates used atom-key access (`device.name`) but `client_midi_devices_updated`
produced string-keyed maps. Result: broken display, 14-device count, "SINCO" appeared
instead of "SMC PAD".

#### New API: `DeviceManager.list_physical_devices/0`

Three private helpers added to `device_manager.ex`:

| Helper | Purpose |
|--------|---------|
| `normalize_device_name/1` | Strips Core MIDI suffixes: `MPC Public/Private/MIDI Port A-B`, `-Private/-Master`, ` Port N` |
| `coalesce_by_prefix/1` | Merges shorter name groups into longer ones — "SINCO" → "SINCO SMC-PAD" |
| `group_by_physical_device/1` | Groups ports by normalized name → physical device maps |

Physical device map shape:
```elixir
%{
  name: "MPC Live II",          # display name (normalized)
  physical_name: "MPC Live II",
  direction: :duplex,
  type: :unknown,
  status: :connected,
  port_count: 8,                # 8 Core MIDI ports for this device
  port_ids: ["input:0", ...],   # all raw port_ids (for PubSub subscribe)
  port_id: "input:0",           # primary (for UI bindings — backwards compat)
  ports: [%{...}, ...]          # full raw port list
}
```

Before / After:
- MIDI badge in header: **14** → **2**
- Device list in settings panel: 14 raw ports → **MPC Live II** + **SINCO SMC-PAD**
- SMC Pad now visible everywhere it was previously hidden
