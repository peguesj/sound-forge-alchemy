components subscribe to `playback:state` instead of maintaining duplicate assigns.

### US-DAW-001: DAW Track Status Badges + Pipeline Actions (commit `fb1f6e6`)

Visual pipeline state system in the DAW header:

| Badge | Condition |
|-------|-----------|
| Spotify | `track.spotify_url` present |
| Downloaded | completed download job + file exists on disk |
| File Missing | completed download job but file deleted |
| Processed | at least one stem |
| Analyzed | `track.bpm` set |

Contextual action buttons:
- **Download Track** — shown when not downloaded (or file missing)
- **Separate Stems** — shown when downloaded + file ok, no stems
- **Analyze Track** — shown when downloaded + file ok
- Buttons hidden when track is fully processed

## Architecture Improvements

```
Physical Device (USB/Network MIDI)
        |
   MidiAdapter / OscAdapter          ← SoundForge.ControlSurface
        |
   ActionBus (tab-context topics)    ← US-C03: no cross-tab leakage
        |
   ActionTranslator                  ← vendor-specific dictionaries
        |
   ControllerFingerprints (ETS)      ← device recognition
        |
   MIDI Mapping (Ecto)               ← tab_context, preset_name
        |
   DJ / DAW / Library handlers       ← 3 extracted domain modules

PlaybackBus GenServer                ← US-C04: unified transport
   ├── DJ deck state
   ├── DAW timeline state
   └── Pads beat state
```
